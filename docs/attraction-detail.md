# 行程概览 · 景点详解

## 概览布局

- 景点卡片直接平铺，不再使用 Swiper 3D 轮播；桌面 3 列、平板 2 列、手机 1 列。
- 卡片图片固定 4:3，桌面单卡宽约 436px、图高约 326px；图片 `object-fit: cover` + 懒加载。
- 「进入景点」按钮始终显示在卡片底部，不依赖 hover，也不会因 3D 层级而点不到。

## 交互约定

在「行程概览」的景点卡片上点击图片或底部按钮时：

- **不再切换**到「每日行程」，URL、当前分区与滚动上下文都保持在概览内。
- 在卡片下方、概览卡片内部就地展开详解面板，不弹全屏 Modal。
- 点击其他景点的进入按钮，同一面板原地更新；点击右上角关闭按钮收起。
- 移动端单列排版。

面板包含：

1. 景点名、所属天、类别、地址、建议停留与门票；
2. **3 张实拍图**（大图 + 两张缩略图，按实际像素面积优先高清图）；
3. 一句话整体印象；
4. **历史背景**（年代、沿革、关键人物/事件）；
5. **有趣好玩**（3—5 条冷知识、传说、建筑巧思、本地玩法、拍照点）；
6. **实用提示**（门票、开放时间、预约、动线建议）。

## 景点图片

`GET /api/poi/gallery?name=钟楼&city=西安&limit=3`

- 优先使用高德 POI 详情中的实拍图，按城市 + 景点名消歧，过滤“地铁站 / 售票处 / 停车场”等干扰项；
- 统一转 HTTPS，最多 3 张；`store.is.autonavi.com` 图片追加 `?type=pic` 取原图；
- 结果写入 `backend/data/poi_photos/<hash>.json` 缓存 7 天；
- 卡片使用去掉 `?type=pic` 的缩略图（首屏省流量），详情使用原图；
- 高德无图时才回退到小红书 `name` 代理，卡片加载失败也会自动回退；
- 详情面板预加载图片后按 `naturalWidth × naturalHeight` 排序，大图限制在 960px 宽，避免低清图被强行放大。

## 内容来源与缓存

`POST /api/attractions/guide`

```json
{
  "name": "钟楼",
  "city": "西安",
  "address": "西安市碑林区东大街与西大街交汇处",
  "description": "西安钟楼为长安城正中心……",
  "category": "历史古迹"
}
```

返回：

```json
{
  "success": true,
  "data": {
    "name": "钟楼",
    "city": "西安",
    "overview": "……",
    "history": "……",
    "fun_facts": ["……"],
    "tips": ["……"],
    "source": "curated"
  }
}
```

优先级：

1. **本地精选**：`backend/app/data/attraction_guides.json`，覆盖西安常见景点，离线可用；
2. **本地缓存**：`backend/data/guides/<hash>.json`，同一景点不重复调用模型；
3. **LLM 生成**：使用现有 OpenAI 兼容配置（DeepSeek），JSON 输出并做结构校验；
4. **兜底整理**：模型不可用时，用行程简介整理出可读内容，并在面板底部标注来源。

LLM 配置只读复用，不修改 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL_ID`。

## 热门景点发现页

- 入口：行程概览的「发现更多热门景点」卡片，以及顶部「热门景点」独立分区。
- 数据：`GET /api/attractions/popular?city=南京&exclude=南京博物院,总统府&limit=12`，从高德 POI 中筛选景点类型，过滤当前行程已有景点，按评分/实拍图排序。
- 卡片展示名称、类别、评分、地址、简介与实拍图；点击「查看介绍」打开详情。
- 详情直接复用本页的 `OverviewAttractionDetail` 模板与 `POST /api/attractions/guide`：
  - 同样的历史背景 / 有趣好玩 / 实用提示 / 门票与预约说明；
  - 票价未知时显示“票价以景区公告为准”，不误标为免费；
  - 顶部标签使用「热门景点」，不改动模板的版式结构。
- 添加：选择「加入日期」后点击「加入行程」，调用现有 `POST /api/plans/{plan_id}/places`，按景点类型写入当天行程并实时重算预算。
- 同步：添加完成后刷新行程与地点列表，并标记地图为待刷新；进入地图时重绘 marker 与路线。
- 更换/更新阶段：添加请求进行期间显示全屏锁定遮罩「更换阶段：正在更新行程与路线，请稍候…」，同时给内容区加 `inert`，鼠标、键盘与焦点都无法操作背景页面，避免重复添加或切换页面造成状态竞争。

## 刷新地图

「刷新地图」原先在概览/预算分区下直接初始化地图，容器 `display:none` 导致尺寸为 0，
AMap 会抛 `Invalid Object: Pixel(NaN, NaN)` 并提示“地图加载失败”。现在的流程：

1. 若当前不在「景点地图」，先切到地图分区；
2. 等待 `nextTick` + `requestAnimationFrame`，确认容器有实际高度；
3. 已有 AMap 实例时只做轻量刷新（`resize` + 重绘标记/路线），避免反复销毁 WebGL 实例造成卡顿；
4. 没有实例或轻量刷新失败时才完整重建，并用 `mapInitGeneration` 取消旧初始化、避免旧实例回写；
5. 重建期间显示「正在加载地图…」遮罩，AMap `complete` 或 6 秒兜底后隐藏，避免出现“提示成功但底图空白”。

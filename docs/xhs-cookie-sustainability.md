# 小红书 Cookie 长期抓取实施方案

> 适用范围：在用户明确授权、遵守小红书服务条款与 robots 规则的前提下，读取公开笔记与公开景点信息，用于个人旅行规划。
>
> 本方案不包含验证码绕过、代理池、账号池、伪造设备指纹、批量注册等规避平台风控的手段。可持续的前提是**低频、可解释、可降级、可审计**，而不是对抗平台。

## 1. 现状与问题

当前实现的关键位置：

- `backend/app/services/xhs_service.py`
  - `get_xhs_client()` 直接读取 `settings.xhs_cookie`；
  - `XhsNativeClient.search_notes()` 每次请求重新签名；
  - 只把 `code=300011` 或包含“异常”的响应识别为 Cookie 失效；
  - 请求超时 15 秒，没有统一重试、限流、熔断；
  - Cookie 失效后直接抛给规划流程。
- `backend/app/services/xhs_sign/sign_util.py`
  - 通过 Node 执行签名 JS；
  - 已修复 JScript 回退导致的 `SyntaxError: 缺少 ':'`。
- 配置
  - Cookie 存在 `runtime_settings.json`，是明文；
  - 没有会话状态、探测、刷新、审计。

长期运行需要补齐的不是“更快的抓取”，而是**会话生命周期、节流、缓存、降级和可观测性**。

## 3. 调度方式

### 3.1 任务类型

1. **用户触发任务**：用户提交行程时，按城市/关键词即时查询；最高优先级。
2. **缓存预热任务**：对近期访问城市、热门城市提前刷新；低优先级。
3. **定时校验任务**：每日检查 Cookie 状态，不做大规模抓取。
4. **重试任务**：网络/限流失败的延迟重试；不重试鉴权失败。

### 3.2 队列与优先级

单实例部署优先使用 SQLite 任务表 + 进程内 `asyncio` worker，避免引入 Redis 的额外运维成本：

```text
xhs_jobs(
  id, job_type, query_key, priority, status,
  attempts, next_run_at, locked_at, last_error, created_at
)
```

- 全局并发：1–2 个 worker；
- 单 Cookie 并发：1；
- 队列上限：例如 200，满时拒绝低优先级任务；
- 优先级：`user > scheduled > prefetch > retry`；
- 任务按 `query_key` 幂等，重复提交只保留一个。

### 3.3 触发策略

- 用户请求：立即入队；若缓存新鲜则直接返回，不请求平台；
- 缓存 TTL：搜索/笔记 6–24 小时，图片 6 小时；
- 过期策略：`stale-while-revalidate`，先返回旧缓存，再后台刷新；
- 定时预热：每天低峰时段（如 03:00–06:00）加随机抖动；
- 只对“最近 30 天有访问/有行程”的城市预热，避免无边界抓取。

## 4. Cookie 获取、加密与持久化

### 4.1 获取方式

优先顺序：

1. **官方开放平台/授权接口**（如果可用）；
2. 用户在浏览器登录小红书后，通过设置页粘贴/导入 Cookie；
3. 提供“浏览器辅助重新登录”：
   - 打开官方登录页；
   - 用户扫码或输入账号；
   - 登录成功后由浏览器扩展/本地助手把 Cookie 写入后端授权接口；
   - 不保存密码，不自动处理验证码。

不建议：

- 后端保存账号密码；
- 自动绕过验证码；
- 多账号池轮换；
- 从第三方购买 Cookie。

### 4.2 必填字段与校验

导入时校验：

- 是否为合法 Cookie 字符串或浏览器导出的 JSON；
- 是否包含 `a1`、`web_session`、`webId` 等关键字段；
- 长度、字符集、重复键；
- 用一次低成本的只读探测确认可用。

不把 Cookie 回传到前端；设置页只显示掩码和状态。

### 4.3 加密存储

```text
xhs_sessions(
  id,
  account_label,
  cookie_cipher,        -- Fernet/DPAPI 加密
  cookie_hash,          -- 用于审计比对，不可逆
  status,               -- active/degraded/expired/needs_login/disabled
  created_at,
  last_ok_at,
  last_probe_at,
  fail_count,
  expires_hint,
  user_agent,           -- 与导入浏览器保持一致
  note
)
```

要求：

- 密钥来自 `XHS_COOKIE_KEY` 环境变量/密钥管理服务，不写入仓库；
- Windows 本地可用 DPAPI 作为二次保护；
- 数据库文件权限限制；
- 日志、异常、接口响应统一脱敏；
- 迁移现有 `runtime_settings.json` 明文 Cookie，迁移后清除明文。

### 4.4 Cookie 轮换

- 支持一个 `active` + 一个 `standby`（同一合法账号的会话轮换，不是账号池）；
- 新 Cookie 导入后先探测，成功才切换；
- 保留旧会话一段时间用于回滚；
- 每次切换写审计日志。

## 5. 失效检测与刷新策略

### 5.1 被动检测

在适配器统一识别：

| 信号 | 分类 |
|---|---|
| HTTP 401/403 | 鉴权失败 |
| `code=300011` | 风控/Cookie 失效 |
| 返回 HTML/登录页 | 会话失效 |
| `success=false` 且 msg 含“登录/异常” | 会话异常 |
| 连续空结果且其他查询正常 | 降级/可疑 |
| `ProgramError`/签名失败 | 运行时错误，不是 Cookie |

### 5.2 主动探测

- 每 10–15 分钟最多一次轻量探测；
- 使用固定只读查询（例如固定城市+固定关键词）；
- 成功：更新 `last_ok_at`，清除失败计数；
- 失败：进入 `degraded`，按指数退避重试；
- 连续失败：`expired`，停止该会话的所有抓取。

### 5.3 状态机

```text
ACTIVE
  ├─ 轻微失败 → DEGRADED（退避，继续有限尝试）
  ├─ 401/300011/登录页 → EXPIRED
  └─ 连续超时 → DEGRADED

DEGRADED
  ├─ 探测成功 → ACTIVE
  └─ 多次失败 → EXPIRED

EXPIRED
  └─ 用户重新登录/导入新 Cookie → ACTIVE
```

### 5.4 “自动刷新”的边界

Web Cookie 没有可靠的静默 refresh token。所谓自动刷新应定义为：

1. **自动检测**过期；
2. **自动暂停**抓取与熔断；
3. **自动通知**用户/管理员；
4. **自动打开**重新登录流程；
5. 用户完成登录后，**自动捕获并加密写入**新 Cookie。

不应实现：

- 自动填写密码；
- 自动破解验证码；
- 伪造设备指纹；
- 用其他账号顶替。

### 5.5 失效后的降级

- 返回缓存数据并标注“数据可能过期”；
- 攻略聚合页显示“小红书需重新登录”，其他平台继续；
- 不阻塞整个旅行计划生成；
- 超过缓存有效期时，明确提示“暂无小红书数据”，不编造。

## 6. 请求频率与并发控制

### 6.1 限流

建议保守默认值，全部可配置：

```text
全局：1–2 并发
单 Cookie：1 并发
搜索：1 次 / 4–6 秒
详情：1 次 / 2–3 秒
每小时：≤ 300 次（按账号）
每天：按实际使用量设置硬上限
```

- 令牌桶 + 滑动窗口；
- 请求间加 0.5–2 秒随机抖动；
- 遵守 `Retry-After`；
- 429/5xx 指数退避 + 抖动；
- 连续失败打开熔断器。

### 6.2 减少请求量

- 搜索结果只取前 1–2 页；
- 只对排名靠前的笔记拉详情；
- 同一 `query_key` 合并；
- 图片按 URL 哈希缓存；
- 优先使用缓存和已结构化数据；
- 不做全站爬取、不做无限翻页。

## 7. 反爬与风控应对（合规版）

### 7.1 原则

- 只读取公开内容；
- 遵守平台服务条款、robots、频率限制；
- 不绕过验证码、不伪造指纹、不使用代理池/账号池；
- 不进行登录、点赞、评论、发布等写操作；
- 不抓取非公开/付费/私密内容；
- 数据只用于用户自己的行程规划。

### 7.2 工程措施

- 固定、真实的 User-Agent，与导入 Cookie 的浏览器保持一致；
- 不随机伪造浏览器指纹；
- 低频、串行、可暂停；
- 遇到 300011/登录页立即停止，不重试风暴；
- 熔断后进入冷却期；
- 记录每次请求的查询、状态、耗时、错误分类（不含 Cookie）；
- 提供管理员“一键停用小红书来源”开关。

### 7.3 风险信号

- 300011 连续出现；
- 登录页/验证码页比例上升；
- 空结果率突然升高；
- 响应时间异常；
- 同一账号短时间请求过多。

触发后：降级、暂停、通知，而不是换代理继续。

## 8. 数据清洗与存储

### 8.1 原始层

保存：

- `note_id`、URL、标题、正文摘要、作者、发布时间；
- 互动数据（如点赞/收藏，若接口返回）；
- 图片 URL；
- `fetched_at`、`query_key`、`schema_version`、`content_hash`；
- HTTP 状态与错误分类（不含敏感头）。

原文只保存必要片段，避免完整转载；原始响应设置 7–30 天 TTL。

### 8.2 清洗

- HTML 标签、脚本、广告、二维码文案去除；
- 全角/半角、空白、重复标点归一；
- 标题/正文去重（note_id + content_hash）；
- 低质量过滤：空正文、纯广告、重复搬运、登录墙；
- 语言识别；
- 敏感信息/PII 脱敏；
- 景点别名归一（博物院/南博等）；
- 结构化：景点、路线、时长、预算、预约、闭馆、交通；
- 每条结论保留 `source_id`、`evidence`、`confidence`。

### 8.3 存储表

```text
xhs_notes
xhs_note_media
xhs_queries
xhs_fetch_logs
xhs_sessions
xhs_jobs
```

- 结构化数据 TTL 30–90 天；
- 聚合统计可长期保留；
- 图片存对象存储/本地缓存，按哈希命名；
- SQLite 适合单实例；多实例时迁移 PostgreSQL + Redis。
- 备份：每日数据库备份，保留 7–30 天；恢复演练。

## 9. 异常处理与监控告警

### 9.1 错误分类

```text
AUTH        401/403/300011/登录页
RATE_LIMIT  429/频率限制
NETWORK     超时/连接失败/DNS
SIGNATURE   Node/签名运行时错误
PARSE       JSON/HTML 结构变化
CONTENT     空结果/低质量/重复
STORAGE     DB/磁盘/加密失败
```

### 9.2 重试策略

| 类型 | 策略 |
|---|---|
| NETWORK | 最多 2 次，指数退避 + 抖动 |
| RATE_LIMIT | 遵守 Retry-After，退避后重试 |
| AUTH | 不重试，立即标记失效 |
| SIGNATURE | 不重试，告警（通常是运行时/依赖问题） |
| PARSE | 不重试，记录样本并告警 |
| CONTENT | 不重试，标记质量 |

### 9.3 指标

- 请求数、成功/失败数、成功率；
- P50/P95 延迟；
- 429/300011/登录页次数；
- 空结果率；
- 签名失败数；
- 队列深度、任务等待时间；
- 缓存命中率；
- Cookie 年龄、最后成功时间；
- 数据写入失败/磁盘使用。

### 9.4 告警阈值（示例）

- 300011 在 10 分钟内 ≥ 1：高优先级；
- 鉴权失败连续 ≥ 3：高优先级；
- 成功率 30 分钟 < 80%：警告；
- 签名失败 ≥ 1：高优先级（应为 0）；
- 队列深度 > 50 持续 10 分钟：警告；
- P95 延迟 > 10 秒：警告；
- 空结果率 > 60% 持续 30 分钟：调查；
- Cookie 超过 7 天未验证：提醒。

告警通道：日志、Webhook、邮件；管理页展示状态。

### 9.5 日志与审计

- 结构化 JSON 日志；
- 统一脱敏 `cookie`、`authorization`、`set-cookie`；
- 每次会话导入/切换/失效写审计；
- 保存请求 ID，串联任务、查询、响应、存储。

## 10. 合规与稳定性

### 10.1 合规

- 用户授权与知情：明确说明会访问小红书公开内容；
- 遵守平台条款与 robots；
- 不绕过付费/私密/登录墙；
- 不存储密码；
- Cookie 加密、最小权限、可删除；
- 数据保留期限与删除机制；
- 只保存摘要/结构化结论，控制引用长度；
- 来源标注：平台、作者、链接、时间；
- 遵守个人信息保护相关法规，不采集无关个人信息。

### 10.2 稳定性

- 缓存优先、异步刷新；
- 单平台失败不影响整体；
- 熔断、冷却、kill switch；
- 队列限流与优雅停机；
- 数据库备份与迁移脚本；
- 版本化数据 schema；
- 可回滚的 Cookie 切换；
- 容量规划：磁盘、图片缓存、日志轮转。

## 12. 实施顺序

## 13. 验收标准

1. Cookie 不以明文出现在代码、日志、接口响应、Git 中；
2. 300011/401 在一次请求内被识别，停止该会话抓取；
3. 失效后 1 分钟内管理页可见，并给出重新登录入口；
4. 单账号并发 ≤ 1，全局并发 ≤ 2，限流可配置；
5. 429/5xx 有退避，无重试风暴；
6. 签名失败有独立告警，不与 Cookie 失效混淆；
7. 缓存命中时不发请求，过期时先返回旧数据；
8. 每个结构化结论有来源、时间、证据片段；
9. 平台失败不阻塞其他来源和最终行程；
10. 有备份、恢复演练和 kill switch。

## 14. 当前代码的落地改造点
